# Knowledge Structuring

Give loose notes a shape that can be reused.

## Process
1. List raw items without editing yet.
2. Name the job of this knowledge (decide, teach, remember, operate).
3. Choose one primary structure: hierarchy, matrix, timeline, workflow, argument map, or concept glossary + relations.
4. Move each item once. Merge duplicates. Park leftovers.
5. Write the framework so a stranger could use it.

## Output
- Chosen structure + why
- The framework itself
- Leftover items that did not fit
- 3 next uses (FAQ, SOP, brief, deck, wiki page)

## Rules
- Do not add a second competing framework "for completeness".
- Keep original wording when it is already precise.
